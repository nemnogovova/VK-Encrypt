# 🔒 VK Шифратор

Расширение для браузера (Manifest V3), обеспечивающее **сквозное (end-to-end) шифрование** сообщений в ВКонтакте. Сообщения шифруются на стороне отправителя и расшифровываются на стороне получателя — сервер VK видит только нечитаемый шифротекст.

## ✨ Возможности

- **Прозрачное шифрование** — сообщения шифруются автоматически при отправке
- **Автоматическая расшифровка** — входящие зашифрованные сообщения расшифровываются «на лету»
- **AES-256-GCM** — надёжный алгоритм с аутентификацией данных
- **PBKDF2** — защита от перебора парольных фраз
- **Визуальная индикация** — иконки 🔓/🔐 показывают статус каждого сообщения
- **Индикатор состояния** — значок на странице VK и бейдж расширения отображают статус шифрования

## 📦 Установка

### Google Chrome / Яндекс Браузер / Microsoft Edge

1. **Скачайте** или склонируйте репозиторий:
   ```bash
   git clone <url-репозитория>
   ```

2. Откройте страницу расширений:
   - **Chrome**: введите в адресной строке `chrome://extensions`
   - **Яндекс Браузер**: `browser://extensions`
   - **Edge**: `edge://extensions`

3. Включите **Режим разработчика** (переключатель в правом верхнем углу страницы).

4. Нажмите **«Загрузить распакованное расширение»** (Load unpacked).

5. Выберите папку `VK Encrypt` (ту, в которой находится файл `manifest.json`).

6. Расширение появится в списке и будет готово к работе. Иконка 🔒 появится на панели расширений.

> **Примечание:** При обновлении файлов расширения нажмите кнопку обновления (🔄) на карточке расширения на странице `chrome://extensions`.

## 🚀 Использование

### Настройка

1. Нажмите на иконку расширения 🔒 на панели браузера — откроется popup-окно настроек.

2. Введите **ключ шифрования** (парольную фразу) в поле «Ключ шифрования».
   > ⚠️ **Важно:** Одинаковый ключ должен быть установлен у обоих собеседников. Обменяйтесь ключом через защищённый канал (лично, через другой мессенджер с шифрованием и т.д.).

3. Включите переключатель **«Шифрование активно»**.

4. Нажмите **«Сохранить»**.

5. Статус изменится на «Шифрование активно» (зелёный индикатор), а на странице VK в левом нижнем углу появится значок 🔒.

### Отправка зашифрованных сообщений

1. Откройте диалог в VK.
2. Напишите сообщение как обычно.
3. Нажмите **Enter** или кнопку отправки — сообщение будет **автоматически зашифровано** перед отправкой.
4. В чате отправленное сообщение отобразится как `🔐ENC:<зашифрованные данные>`.

### Получение и расшифровка

- Если у получателя установлено расширение с тем же ключом — сообщение автоматически расшифровывается и отображается с иконкой 🔓 (расшифровано).
- Если ключ неверный — сообщение остаётся зашифрованным с иконкой 🔐 и подсказкой «Зашифровано — неверный ключ».
- Без расширения получатель увидит только `🔐ENC:` и строку из случайных символов.

### Отключение шифрования

Снимите галочку «Шифрование активно» в popup-окне и нажмите «Сохранить» — сообщения будут отправляться как обычный текст.

## 🔐 Методы шифрования

Расширение использует исключительно **Web Crypto API** — стандартный криптографический интерфейс браузера, реализованный на нативном уровне.

### Общая схема

```
Пароль (ключ-фраза)
        │
        ▼
┌───────────────┐
│    PBKDF2     │  ← salt (16 байт, случайный)
│  100 000 iter │
│   SHA-256     │
└───────┬───────┘
        │
        ▼
   AES-256 ключ
        │
        ▼
┌───────────────┐
│   AES-GCM     │  ← IV (12 байт, случайный)
│   256 бит     │
└───────┬───────┘
        │
        ▼
  Шифротекст + Authentication Tag
        │
        ▼
  🔐ENC: base64( salt ‖ iv ‖ ciphertext )
```

### 1. Выработка ключа — PBKDF2

| Параметр       | Значение      |
|----------------|---------------|
| Алгоритм       | PBKDF2        |
| Хеш-функция    | SHA-256       |
| Итерации        | 100 000       |
| Длина salt      | 16 байт (128 бит) |
| Выходной ключ   | 256 бит       |

**PBKDF2** (Password-Based Key Derivation Function 2) — функция формирования ключа из пароля. Применяется для превращения произвольной парольной фразы в криптографически стойкий 256-битный ключ.

- **Salt** (соль) — случайная 16-байтовая последовательность, генерируемая для каждого сообщения заново через `crypto.getRandomValues()`. Обеспечивает уникальность производного ключа даже при одинаковом пароле.
- **100 000 итераций** — замедляет перебор паролей (brute-force), делая атаку вычислительно дорогой.

### 2. Шифрование — AES-256-GCM

| Параметр       | Значение      |
|----------------|---------------|
| Алгоритм       | AES-GCM       |
| Длина ключа     | 256 бит       |
| Длина IV (nonce)| 12 байт (96 бит) |
| Authentication tag | 128 бит (встроен) |

**AES-GCM** (Advanced Encryption Standard — Galois/Counter Mode) — режим блочного шифрования с аутентификацией.

- **AES-256** — симметричный блочный шифр с ключом 256 бит, стандарт NIST. Используется правительствами и военными для защиты информации уровня «совершенно секретно».
- **GCM** (Galois/Counter Mode) — режим работы, обеспечивающий одновременно конфиденциальность и аутентичность данных (AEAD — Authenticated Encryption with Associated Data). Встроенный **authentication tag** гарантирует, что шифротекст не был изменён.
- **IV** (Initialization Vector) — 12-байтовый одноразовый номер (nonce), генерируемый случайно для каждого сообщения. Гарантирует, что одинаковые сообщения с одним ключом дают разный шифротекст.

### 3. Формат зашифрованного сообщения

```
🔐ENC:<base64-строка>
```

Base64-строка содержит конкатенацию трёх компонентов:

| Смещение (байты) | Длина   | Содержимое        |
|-------------------|---------|--------------------|
| 0–15              | 16 байт | Salt (PBKDF2)      |
| 16–27             | 12 байт | IV (AES-GCM nonce) |
| 28+               | N байт  | Шифротекст + GCM tag |

При расшифровке: salt и IV извлекаются, из пароля и salt выводится ключ, после чего AES-GCM расшифровывает и верифицирует данные.

### Почему это надёжно

- **Каждое сообщение** использует уникальные salt и IV → одинаковые тексты дают разный шифротекст.
- **AEAD** (GCM) защищает от подмены шифротекста — любая модификация обнаруживается при расшифровке.
- **PBKDF2 с 100K итерациями** затрудняет перебор паролей.
- **Web Crypto API** — проверенная реализация, работающая на уровне браузера, а не пользовательский JavaScript-код.

## 🏗 Архитектура

### Компоненты

| Файл             | Роль                                                        |
|------------------|-------------------------------------------------------------|
| `manifest.json`  | Манифест расширения (Manifest V3), разрешения и точки входа |
| `crypto.js`      | Криптографический модуль (PBKDF2 + AES-GCM)                |
| `content.js`     | Content script — перехват отправки, расшифровка сообщений   |
| `content.css`    | Стили индикаторов и расшифрованных сообщений                |
| `background.js`  | Service Worker — управление бейджем расширения              |
| `popup/`         | UI настроек (ключ, включение/выключение)                    |

### Поток данных

**Отправка сообщения:**
1. Пользователь вводит текст и нажимает Enter.
2. `content.js` перехватывает событие `keydown` (или `click` на кнопку отправки).
3. Текст передаётся в `VKCrypto.encrypt()` с текущим ключом.
4. `crypto.js` генерирует salt + IV, выводит AES-ключ через PBKDF2, шифрует AES-GCM.
5. Результат (`🔐ENC:<base64>`) подставляется в поле ввода, после чего эмулируется нажатие Enter.

**Получение сообщения:**
1. `MutationObserver` в `content.js` отслеживает появление новых DOM-элементов.
2. При обнаружении контейнеров `.MessageText` / `.MessagePreview` с паттерном `🔐ENC:` запускается расшифровка.
3. `VKCrypto.decrypt()` извлекает salt, IV, шифротекст, выводит ключ и расшифровывает.
4. При успехе содержимое заменяется расшифрованным текстом с иконкой 🔓.
5. При неудаче (неверный ключ) отображается иконка 🔐.

## ⚠️ Безопасность и ограничения

### Безопасность
- Ключ хранится в `chrome.storage.local` — доступен только данному расширению.
- Шифрование и расшифровка происходят полностью на устройстве пользователя.
- Серверы VK не получают открытый текст — только шифротекст.

### Ограничения
- **Не шифруются:** изображения, вложения, стикеры, голосовые сообщения — только текстовые сообщения.
- **Обмен ключом** происходит вручную — расширение не реализует протокол согласования ключей (Diffie-Hellman и т.п.).
- **Один ключ на всё расширение** — нет возможности задать разные ключи для разных диалогов.
- Расширение зависит от DOM-структуры VK — при значительном обновлении интерфейса VK могут потребоваться доработки селекторов.
- Надёжность шифрования напрямую зависит от сложности выбранного пароля — используйте длинные фразы (12+ символов).
