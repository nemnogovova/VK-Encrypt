# 🔒 VK Шифратор

Расширение для браузера (Manifest V3), обеспечивающее **сквозное (end-to-end) шифрование** сообщений в ВКонтакте на основе протокола **ECDH** (Elliptic-Curve Diffie-Hellman). Ключи генерируются прямо в браузере и никогда не покидают устройство — сервер VK видит только нечитаемый шифротекст.

## ✨ Возможности

- **Отдельный ключ для каждого чата** — разные диалоги шифруются независимо
- **ECDH-рукопожатие прямо через VK** — обмен публичными ключами происходит через сообщения, ручная передача ключей не нужна
- **Emoji-отпечаток (Safety Numbers)** — 6 эмодзи для защиты от атаки «человек посередине»; сверьте их с собеседником по голосу или вне VK
- **Встроенная панель** — управление шифрованием прямо в шапке диалога, в нативном стиле VK
- **Прозрачное шифрование** — сообщения шифруются и расшифровываются автоматически
- **AES-256-GCM + HKDF** — аутентифицированное шифрование; любая подмена шифротекста обнаруживается
- **Бейдж расширения** — показывает количество чатов с активным шифрованием

## 📦 Установка

### Google Chrome / Яндекс Браузер / Microsoft Edge

1. **Скачайте** или склонируйте репозиторий:
   ```bash
   git clone <url-репозитория>
   ```

2. Откройте страницу расширений:
   - **Chrome**: `chrome://extensions`
   - **Яндекс Браузер**: `browser://extensions`
   - **Edge**: `edge://extensions`

3. Включите **Режим разработчика** (переключатель в правом верхнем углу).

4. Нажмите **«Загрузить распакованное расширение»** и выберите папку с `manifest.json`.

5. Расширение появится в списке — иконка 🔒 появится на панели браузера.

> **Обновление:** при изменении файлов нажмите 🔄 на карточке расширения на странице `chrome://extensions`.

## 🚀 Использование

### Первый запуск

1. Откройте `vk.com/im` и перейдите в нужный диалог.
2. В шапке диалога появится встроенная панель **VK Шифратора** с кнопкой «🤝 Рукопожатие».
3. Нажмите её — расширение сгенерирует ключевую пару и отправит публичный ключ собеседнику.

### Обмен ключами (рукопожатие)

4. У собеседника появится уведомление «🔑 Входящий запрос шифрования» — он нажимает **«✓ Принять»**.
5. Обе стороны видят **одинаковые 6 эмодзи** (Safety Numbers).
6. Позвоните собеседнику или напишите вне VK — убедитесь, что эмодзи совпадают, затем нажмите **«✓ Совпадают»**.
7. Шифрование активировано. Все последующие сообщения шифруются/расшифровываются автоматически.

### Управление

- **Тоггл** в панели или popup — включить/выключить шифрование для текущего чата без сброса ключа.
- **Кнопка ↺** — сброс ключа и начало нового рукопожатия.
- **Popup-расширения** — список всех чатов с ключами, управление каждым из них.

### Отправка и получение

- При включённом шифровании нажмите **Enter** или кнопку отправки — сообщение шифруется автоматически.
- Входящие зашифрованные сообщения расшифровываются «на лету» и отображаются с иконкой 🔓.
- Если ключ не совпадает — сообщение остаётся с иконкой 🔐.

## 🤝 Протокол рукопожатия (ECDH)

```
Алиса                                   Боб
  │                                      │
  │  нажимает «Рукопожатие»              │
  │  генерирует keypair_A (P-256)        │
  │─── 🔐HS-INIT:<pubKey_A_base64> ─────►│
  │                                      │  видит входящий INIT
  │                                      │  генерирует keypair_B (P-256)
  │                                      │  вычисляет shared = ECDH(privB, pubA)
  │                                      │  passphrase = HKDF(shared)
  │                                      │  fingerprint = SHA-256(sort([pubA,pubB]))→6 emoji
  │◄── 🔐HS-ACK:<pubKey_B_base64> ───────│
  │                                      │  показывает fingerprint, ждёт подтверждения
  │  вычисляет shared = ECDH(privA, pubB)│
  │  passphrase = HKDF(shared)           │
  │  fingerprint = SHA-256(sort([pubA,pubB]))→6 emoji
  │                                      │
  │  [сверка эмодзи вне VK]             │
  │  нажимает «✓ Совпадают»              │  нажимает «✓ Совпадают»
  │                                      │
  │◄══════ AES-256-GCM шифрование ══════►│
```

**Защита от MitM:** VK видит оба публичных ключа при транзите, но не может незаметно подменить их — любая подмена изменит отпечаток, и пользователи это заметят при сверке эмодзи. После сверки все сообщения защищены AES-GCM, чей authentication tag не позволяет VK подменять шифротекст.

## 🔐 Методы шифрования

Расширение использует исключительно **Web Crypto API** — стандартный криптографический интерфейс браузера.

### Схема ключевого обмена

```
ECDH P-256 (keypair_A × keypair_B)
        │
        ▼
   Shared Secret (256 бит)
        │
        ▼
┌───────────────┐
│     HKDF      │  info = "VK-Encrypt-v1"
│   SHA-256     │  salt = 32 нулевых байта
└───────┬───────┘
        │
        ▼
   Passphrase (64-hex символа)
        │
        ▼
┌───────────────┐
│    PBKDF2     │  ← salt (16 байт, случайный, per-message)
│  100 000 iter │
│   SHA-256     │
└───────┬───────┘
        │
        ▼
   AES-256 ключ
        │
        ▼
┌───────────────┐
│   AES-GCM     │  ← IV (12 байт, случайный, per-message)
│   256 бит     │
└───────┬───────┘
        │
        ▼
  🔐ENC: base64( salt ‖ iv ‖ ciphertext+tag )
```

### Алгоритмы

| Слой              | Алгоритм       | Параметры                          |
|-------------------|----------------|------------------------------------|
| Ключевой обмен    | ECDH P-256     | namedCurve: P-256                  |
| Выработка ключа   | HKDF           | SHA-256, info = "VK-Encrypt-v1"   |
| Симметр. ключ     | PBKDF2         | SHA-256, 100 000 итераций, 16-б salt |
| Шифрование        | AES-256-GCM    | 12-байт IV, 128-бит тег            |
| Отпечаток         | SHA-256        | sort([pubA, pubB]) → 6 emoji       |

### Формат зашифрованного сообщения

```
🔐ENC:<base64-строка>
```

| Смещение | Длина    | Содержимое               |
|----------|----------|--------------------------|
| 0–15     | 16 байт  | Salt (PBKDF2, per-msg)   |
| 16–27    | 12 байт  | IV (AES-GCM nonce)       |
| 28+      | N байт   | Шифротекст + GCM tag     |

## 🏗 Архитектура

### Компоненты

| Файл             | Роль                                                              |
|------------------|-------------------------------------------------------------------|
| `manifest.json`  | Манифест расширения (Manifest V3)                                 |
| `crypto.js`      | Криптомодуль: ECDH, HKDF, PBKDF2, AES-GCM, fingerprint           |
| `content.js`     | Per-chat логика, ECDH-рукопожатие, панель, перехват/расшифровка  |
| `content.css`    | Стили встроенной панели и сообщений (VK CSS-переменные)           |
| `background.js`  | Service Worker — бейдж с количеством активных чатов              |
| `popup/`         | Popup: просмотр всех чатов, кнопки управления рукопожатием        |

### Хранилище

Все данные хранятся в `chrome.storage.local` под ключом `vkEncChats`:

```js
{
  "vkEncChats": {
    "<chatId>": {
      "state":       "none|initiated|received|verifying|active",
      "enabled":     true,
      "myPubKey":    "<base64>",
      "myPrivKey":   { /* JWK */ },
      "theirPubKey": "<base64>",
      "passphrase":  "<64-hex>",
      "fingerprint": "🌀 🦋 🐉 🌸 ⭐ 🎈"
    }
  }
}
```

Приватный ключ хранится как JWK в `chrome.storage.local` — доступен только данному расширению, не синхронизируется.

### Поток данных — отправка

1. Пользователь нажимает Enter / кнопку отправки.
2. `content.js` перехватывает событие (фаза захвата, `stopImmediatePropagation`).
3. Текст → `VKCrypto.encrypt(text, passphrase)` → `🔐ENC:<base64>`.
4. Результат вставляется в поле ввода через `execCommand('insertText')`, затем эмулируется Enter.

### Поток данных — получение

1. `MutationObserver` отслеживает появление `.MessageText` / `.MessagePreview`.
2. Паттерн `<img alt="🔐"> + текстовый узел "ENC:…"` → извлечение payload.
3. `VKCrypto.decrypt(payload, passphrase)` → plaintext.
4. Контейнер заменяется расшифрованным текстом + иконкой 🔓.

## ⚠️ Безопасность и ограничения

### Безопасность

- Приватные ключи никогда не покидают `chrome.storage.local` — доступны только данному расширению.
- Шифрование и расшифровка происходят полностью на устройстве.
- Серверы VK получают только шифротекст; подменить его незаметно невозможно (GCM authentication tag).
- **После** завершения рукопожатия VK не может расшифровать сообщения и не может незаметно подменить шифротекст.

### Ограничения

- **MitM при рукопожатии:** VK видит публичные ключи в транзите и теоретически может подменить их. Защита — сверка emoji-отпечатка вне VK (по голосу, через другой мессенджер и т.д.).
- **Не шифруются:** изображения, вложения, стикеры, голосовые сообщения — только текст.
- **Один браузер:** ключи хранятся локально; на другом устройстве потребуется новое рукопожатие.
- Расширение зависит от DOM-структуры VK — при значительных обновлениях интерфейса VK могут потребоваться правки CSS-селекторов.
